# Kaizen reference

The outside sources behind [`kaizen-guide.md`](kaizen-guide.md) and how their
concepts map onto the journal and patterns practice. Read this when you want a
definition checked, a claim sourced, or a fuller treatment of a concept the
guide only names.

## How to use these sources

The guide is the governing layer. If a source here disagrees with the guide's
working understanding, the guide wins: these sources ground the practice; they
do not govern it.

Each entry links to the live page rather than a copy, because the pages are
third-party content that this repository does not republish. Volatile sources,
Wikipedia and TechTarget in particular, change faster than the lexicon-style
entries. Before leaning on a specific claim, check it against the live page;
drift there degrades sourcing, not the practice's working correctness.

## Sources

| Source | What it adds |
|--------|--------------|
| [Wikipedia — *Kaizen*](https://en.wikipedia.org/wiki/Kaizen) | The broadest foundational article: etymology, postwar and Deming history, the levels of kaizen (point, system, line, plane, cube), 5S, PDCA, the five whys, Genchi Genbutsu, and the seven muda |
| [Lean Enterprise Institute — *Kaizen*](https://www.lean.org/lexicon-terms/kaizen/) | The most authoritative Lean-tradition source. It pairs kaizen with standardized work, quoting Taiichi Ohno: "There can be no kaizen without a standard." It also covers the eight-step kaizen routine, kaizen events, and their common failure modes |
| [Lean Production — *Kaizen*](https://www.leanproduction.com/kaizen/) | Kaizen as "part action plan and part philosophy", standardized work as "living documentation", and PDCA cast as the scientific method: hypothesis, experiment, evaluation, refinement |
| [TechTarget — *What is Kaizen (Continuous Improvement)?*](https://www.techtarget.com/searcherp/definition/kaizen-or-continuous-improvement) | The "10 principles of Kaizen" (including don't accept the status quo, ask why five times, and never stop improving), advantages and disadvantages, and corporate examples |
| [The Lean Way — *What is Continuous Improvement (Kaizen)?*](https://theleanway.net/what-is-continuous-improvement) | A clean introduction: the Kai + Zen etymology, a six-phase improvement cycle, and practical getting-started guidance |
| [MindTools — *Kaizen*](https://www.mindtools.com/af0ltld/kaizen/) | The workplace angle: the muda waste categories translated to knowledge work (movement, time, defects, overprocessing, variations) and an individual "ideas log" |

## How the concepts map onto the practice

The sources describe kaizen as it developed: a manufacturing-floor practice
for line workers with supervisor coaching. Several of its load-bearing
concepts translate directly to the way the guide works.

| Concept | Where it lives in the practice | Primary sources |
|---------|--------------------------------|-----------------|
| **PDCA cycle** (Plan, Do, Check, Act) | Mapped in the guide's *How it works — the PDCA cycle*: Plan is instruction files, skills, and checks; Do is sessions; Check is journal entries; Act is patterns and graduation | Wikipedia, Lean Production |
| **Standardized work as living documentation** | Instruction files, skills, hooks, style guides, and procedures, all source-controlled and updated as patterns graduate | Lean Production, Lean Enterprise Institute |
| **"There can be no kaizen without a standard"** | Why lessons graduate into a standard at all: a journal entry with no standard to update produces no compounding | Lean Enterprise Institute |
| **Five whys and root cause** | The guide's *Writing useful entries*: name the root cause, not just the symptom | Wikipedia, TechTarget |
| **Genchi Genbutsu** ("go to the source") | Why entries record the concrete situation — exact tool, specific flag, what was said versus what happened — rather than a vague description | Wikipedia, Lean Enterprise Institute |
| **Point kaizen** (an immediate fix at the individual level) | A typical journal entry: one observation about one friction, captured without ceremony | Wikipedia |
| **System kaizen** (organized, system-level improvement) | Pattern distillation: when several point observations share a root cause, the pattern targets the system rather than the symptom | Wikipedia |
| **The 10 principles** | The mindset behind the journal: friction signals that the system needs adjustment, not that the practitioner failed | TechTarget |
| **Muda translated to knowledge work** | A checklist for what counts as friction: prompt re-reads, agent retries, redundant context loading, ad-hoc procedures that should be skills | MindTools |
